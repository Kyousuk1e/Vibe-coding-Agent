## 实际场景

| 场景 | 模型调用数 | 执行与断言 |
| --- | --- | --- |
| 记住“蓝鲸七号”项目代号 | 1 | 无工具调用 |
| 纯对话追问代号 | 1 | 无工具调用，回答包含原代号 |
| 计算 `(123+456)*7` | 2 | calculator 结果为 4053，回答与工具结果一致 |
| 搜索上下文压缩资料 | 2 | search 确实执行，mock 标识、来源与非空结果正确 |
| 上海天气与“明天带伞”待办 | 3 | weather 和 todo 执行，保存单条且文字精确匹配的待办 |
| 独立窗口整理周报并记待办 | 2 | todo 执行，第二个 Session 只保存周报待办 |
| 完成之前带伞的待办 | 3 | todo list/complete 执行，原 ID 不变且 done=true |
| 新 Runtime 继续会话 | 1 | 记得项目代号与待办状态，没有修改两份 Session 的待办 |
| 新 Store 读取磁盘状态 | 0 | 状态持久化、窗口归属及待办数量一致 |

验收同时检查自然语言、工具 trace 和保存后的业务状态，不只匹配“已添加”文字。纯对话要求零工具调用；计算检查精确数值；天气和搜索检查模拟来源；待办检查文字、数量、ID 和状态。

## 在当前项目重新执行

本项目的 [scripts/live_smoke.py](../scripts/live_smoke.py) 独立运行。先在项目根目录配置 `.env`，再执行：

```powershell
python scripts/live_smoke.py
```

Windows 可用 `py`。该命令使用真实密钥并产生 API 用量，缺少密钥会明确失败。原始报告写到本项目的 `docs/live-result.json`，默认忽略；公开证据不包含密钥或认证信息。

当前独立文档不将历史调用冒充为本次打包后的重跑。新的结果应保留自己的时间、用量与通过状态。LLM 对不同输入仍可能漏调用，调用方需要核对执行状态；上下文压缩等边界由离线用例补充验证。

新 Runtime 续聊是在同一 Python 进程内重新创建组件，不能当作完整进程崩溃恢复测试。其他验证记录见 [VALIDATION.md](VALIDATION.md)。
