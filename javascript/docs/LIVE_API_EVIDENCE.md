## 首次失败与定向回归

第一次真实测试在“写周报并添加待办”步骤失败：模型直接回答“已添加”，trace 中没有 todo 调用。原断言正确拒绝了该结果。修订 [src/prompt.js](../src/prompt.js)，明确多项请求需要分别完成、文字确认不能代替实际操作，并增加“周报+待办”原生调用示例。

修订后，在三个独立 Session 中进行真实回归，以下输入全部同时满足“todo 调用成功 + 单条待办正确持久化”：

1. 本周完成了 Agent 工具注册，下周准备补测试。帮我写一段简短周报，并添加一条文字恰好为“周五提交周报”的待办。
2. 帮我把“已经完成登录接口，明天调试联调问题”整理成两句周报，顺便记待办：明天联调。
3. 请先记录一条待办：整理测试报告。然后根据本周新增了登录测试和导出测试这两项事实写一段周报。

随后重新执行上表完整验收，全部通过。保留并加强了业务断言，没有通过放宽成功条件掩盖模型漏调用。

## 证据边界

新 Runtime 恢复通过同一进程中新建 app、client、runtime、context、store 并加载原磁盘文件完成，不是完整操作系统进程重启。天气与搜索返回的是模拟数据，只有模型 API 是真实服务。

模型决策不确定，这份记录只证明实际执行过的输入通过。上下文压缩、故障重试、轮次上限等边界由确定性测试覆盖，不能推断任意输入都不会漏调用。原始本地报告默认不提交；公开记录不包含认证凭据。
